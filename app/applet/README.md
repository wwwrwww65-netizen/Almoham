## 2. آلية الربط والتواصل مع راوتر المايكروتك (MikroTik RouterOS Integration)

### أ. دورة حياة المستخدم في الشبكة (Captive Portal Lifecycle):
1. **الاتصال بالوايفاي (Association)**:
   - يتصل هاتف المستخدم بنقطة البث (Access Point).
   - يقوم سيرفر المايكروتك (DHCP Server) بتعيين عنوان IP وقناع شبكة وبوابة للمستخدم (مثال: `192.168.88.25`).
2. **الاحتجاز والتحويل (Captive Portal Hijacking)**:
   - يحاول جهاز العميل الاتصال بالإنترنت (طلب فحص مثل `connectivitycheck.gstatic.com`).
   - يقوم المايكروتك عبر جدار الحماية (NAT Redirect) باعتراض طلب HTTP (المنفذ 80) وتوجيهه إلى منفذ خدمة الهوتسبوت الداخلي.
   - يقوم المايكروتك بقراءة ملف `login.html` واستبدال كافة المتغيرات الخاصة بالمايكروتك بالبيانات الحقيقية ثم إرسال الصفحة للعميل.
3. **التوثيق (Authentication)**:
   - يرسل المستخدم بيانات الدخول إما عبر **HTTP-CHAP** أو **HTTP-PAP**.
   - يتحقق الراوتر من قاعدة البيانات المحلية (Local Users) أو سيرفر الراديوس (User Manager / Radius Server).
4. **فتح الوصول (Authorization)**:
   - عند نجاح المطابقة، ينشئ الراوتر جلسة نشطة (Active Session)، ويحدد السرعة (Queue)، ويبدأ حساب الوقت والبيانات.
   - يتم تحويل المستخدم تلقائياً إلى صفحة `alogin.html` ثم `status.html`.

## 4. كيفية تسجيل الدخول وتشفير كلمة المرور (Authentication & Submission Flow)

يدعم القالب نمطين للتوثيق حسب إعدادات الهوتسبوت في المايكروتك:

### أ. بروتوكول CHAP (Challenge-Handshake Authentication Protocol):
1. عندما يكون خيار `HTTP-CHAP` مفعلاً في الراوتر، يعرّف الراوتر المتغيرين `$(chap-id)` و `$(chap-challenge)`.
2. داخل `login.html`، يتم تفعيل النموذج المخفي `sendin`:
   ```html
   <form name="sendin" action="$(link-login-only)" method="post">
       <input type="hidden" name="username" />
       <input type="hidden" name="password" />
       <input type="hidden" name="dst" value="$(link-orig)" />
       <input type="hidden" name="popup" value="true" />
   </form>
   ```
3. عند الضغط على زر "دخول"، يتم استدعاء دالة `doLogin()` في الجافاسكربت:
   - قراءة رمز الدخول: `var user = document.login.username.value;`
   - تنظيف الرمز من أي مسافات: `user = user.split(' ').join('');`
   - تحويل الرمز إلى أحرف صغيرة: `user = user.toLowerCase();`
   - في شبكات الكروت الموحدة، **اسم المستخدم هو نفسه كلمة المرور**.
   - توليد الهاش الأمني المشفر بواسطة خوارزمية MD5 (`md5.js`):
     $$\text{Password Hash} = \text{MD5}(\$(chap\text{-}id) + \text{user} + \$(chap\text{-}challenge))$$
   - تعيين الهاش في `document.sendin.password.value`.
   - إرسال النموذج المخفي `sendin.submit()` عبر طلب HTTP POST آمن لا يكشف كلمة المرور في الشبكة.

### ب. بروتوكول PAP (Password Authentication Protocol):
- إذا كان الراوتر يستخدم `HTTP-PAP`، يتم إرسال النموذج الأساسي مباشرة إلى `$(link-login-only)` متضمناً `username` و `password` بنص مباشر عبر اتصال آمن.

## 5. محرك تغيير السرعات والربط الخارجي (Bandwidth Switching System)

يحتوي القالب على ميزة اختيار السرعة التفاعلية عبر القائمة المنسدلة:

```html
<select id="speed" onchange="changeProfile(this.value, this.options[this.selectedIndex].text)">
  <option value="512k">سرعه 512 كيلوا بايت</option>
  <option value="1M">سرعة عادية 1 ميجا</option>
  <option value="3M">سرعة متوسطة 2 ميجا</option>
  <option value="10m">4 ميجا سرعه عاليه</option>
</select>
```

### كيف تتم عملية تغيير السرعة للمايكروتك؟
1. عند اختيار المستخدم للسرعة، تنفذ دالة `changeProfile(prof, nAm)`.
2. يُعرض تأكيد: `"هل انت متاكد من رغبتك في تغيير السرعة الي ...؟"`.
3. عند الموافقة، يتم توجيه إطار مخفي `<iframe>` يحمل المعرف `FrameChanger` إلى سكريبت لوحة تحكم خارجية:
   ```
   https://alnser.network/MK_Panel/scripts.php?TYPE=changeProfileByUser&id=68&USER=Hany&ip=$(ip)&mac=$(mac)&prof=[السرعة]
   ```
   - `TYPE=changeProfileByUser`: نوع العملية (تغيير البروفايل من قبل المستخدم).
   - `id=68`: معرف الشبكة في سيرفر لوحة التحكم.
   - `USER=Hany`: اسم المشرف أو صاحب الشبكة.
   - `ip=$(ip)`: عنوان IP المشترك الحالي على الراوتر.
   - `mac=$(mac)`: عنوان MAC المشترك لتمييز جهازه بدقة.
   - `prof`: البروفايل المطلوب (`512k`, `1M`, `3M`, `10m`).
4. سكريبت الـ PHP الخارجي يتصل براوتر المايكروتك عبر **MikroTik RouterOS API (Port 8728)**، ويقوم بتنفيذ أمر تغيير البروفايل أو الـ Queue المخصص للمستخدم لحظياً.
5. يتم حفظ السرعة المختارة محلياً في المتصفح عبر `localStorage.chngProF` لتبقى محددة عند العودة للصفحة.

## 6. نظام الكوكيز وحفظ بيانات الكرت (Cookie Management)

1. **حفظ بيانات الكرت (`rem()` و `hotCookie.min.js`)**:
   - عند تفعيل خيار "حفظ بيانات الكرت" (`input#remember`) والنقر على دخول:
   - يتم إنشاء كوكي يحمل اسم الكرت:
     - `uname=[رمز الكرت]`: بمدة صلاحية 30 يوماً (`259200000 ms`).
     - `error=1`: كوكي مؤقت بمدة صلاحية 5 ثوانٍ يمنع تكرار التحويل عند حدوث أخطاء.
2. **تسجيل الدخول التلقائي بالكوكيز (`checkCookie()` و `cookieLogin()`)**:
   - عند فتح العميل لصفحة الهوتسبوت مجدداً، تقرأ دالة الكوكي الرمز المحفوظ في المتصفح.
   - إذا وجد الكرت ولم يكن هناك خطأ مسجل، يقوم المتصفح تلقائياً بطلب:
     `window.location.href = 'login?username=' + uname;`
     ليتم إدخال المستخدم للإنترنت فورياً دون الحاجة لإعادة كتابة الكرت.
3. **تبديل الكرت وحذف البيانات (`delrem()`)**:
   - في صفحة الحالة `status.html`، يوجد زر "تسجيل بكرت آخر".
   - عند النقر عليه، تنفذ دالة `delrem()` لحذف الكوكيز نهائياً:
     `document.cookie = "uname=; expires=Thu, 01 Jan 1970 00:00:00 GMT; path=/";`
     ثم توجيه المستخدم لصفحة الدخول لكتابة كرت جديد.

## 7. قاموس الأخطاء والحظر والصلاحيات (Error Dictionary & Limits)

تمت ترجمة وتخصيص أخطاء المايكروتك في `login.html` و `errors.txt` إلى العربية بدقة:

| الخطأ في المايكروتك (Error String) | الرسالة المعروضة للمستخدم | السبب والحل في المايكروتك |
| :--- | :--- | :--- |
| `simultaneous session limit reached` | عذراً .. هذا الحساب مستخدم حالياً على جهاز آخر | عدد الأجهزة المتصلة بنفس الكرت تجاوز الحد المسموح في الـ Profile |
| `invalid password` / `invalid username` | خطأ في رمز الدخول .. حاول مرة أخرى | تم إدخال رمز كرت غير موجود في قاعدة بيانات الهوتسبوت |
| `uptime limit reached` | عذراً لقد انتهى الوقت المتاح لك.. | انتهت ساعات العمل المحددة للكرت في خانة Limit Uptime |
| `traffic limit` / `limit reached` | لقد انتهى رصيد تحميل هذا الحساب | استهلك الكرت كامل كمية الميجابايت المحددة في Limit Bytes Total |
| `Expired prepaid card!` | لقد انتهت صلاحية هذا الكرت | تجاوز الكرت تاريخ الصلاحية منذ أول تسجيل دخول (Validity Time) |
| `not allowed to log in from this MAC` | هذا الحساب خاص بجهاز آخر .. لا تستطيع الدخول به | الكرت مقترن بعنوان MAC محدد (MAC Binding / MAC Cookie) |
| `invalid Calling-Station-Id` | هذا الحساب مقترن بجهاز آخر، تواصل بخدمة العملاء | قيود الـ Calling-Station-Id في سيرفر الراديوس (Radius) |
| `no valid profile found` | لقد انتهت صلاحية هذا الحساب . | انتهى ملف تعريف المستخدم أو تم تعطيل البروفايل |
| `not found` | رمز الدخول غير صحيح ، الرجاء المحاولة مرة اخرى | لم يتم العثور على اسم المستخدم في قاعدة المستخدمين |
| `responding` | هناك مشكلة في النظام .. يرجى الإتصال بنا حالاً | خادم الراديوس (Radius Server) لا يستجيب لطلبات الراوتر |

## 10. بنية المحاكي وسيرفر التطوير (Dev Server & Simulator Architecture)

تم ضبط خادم `vite.config.ts` ليعمل كـ **محاكي راوتر مايكروتك كامل (MikroTik RouterOS Simulator)** دون المساس بأي ملف داخل `yyyy`:
- **معالجة المتغيرات**: تحويل كل متغيرات `$(...)` إلى قيم حقيقية متناسقة لحظياً أثناء قراءة الصفحات.
- **محاكاة الدخول والخروج**: اعتراض مسارات `/login` و `/logout` وتوجيه المشترك تلقائياً بين `login.html` و `status.html`.
- **حماية الأخطاء**: توفير استجابات تلقائية لدوال `openLogin`, `checkCookie`, `delrem`, `doLogin` لمنع أي أخطاء في الكونسول.
- **تأمين الموارد**: تقديم ملفات الـ CSS والـ JS ومكتبات الخطوط بنوع المحتوى السليم (MIME types).
